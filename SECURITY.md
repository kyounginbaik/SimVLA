# Security policy

Security fixes are considered for the latest SimVLA release on the default branch. Older releases do not receive separate maintenance. This policy covers SimVLA source and packaging; vulnerabilities in Isaac Sim, cuRobo, OpenPI, and other upstream dependencies should also be reported to their respective maintainers.

To report a potential vulnerability privately, use [GitHub private vulnerability reporting](https://github.com/kyounginbaik/SimVLA/security/advisories/new). Include the affected version or commit, a minimal reproduction, expected impact, and a safe way to verify the issue. Do not post exploit details, credentials, or private data in a public issue. The repository owner must enable GitHub's private vulnerability reporting feature before this route can accept reports; enablement should be checked before publication.

For ordinary bugs and research questions, use the issue templates after removing sensitive data.
